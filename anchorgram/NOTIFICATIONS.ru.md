# Уведомления iOS

В предоставленном профиле разрешено aps-environment=production. Раньше путь unsigned-сборки через Xcode-managed signing записывал пустое окружение APNs. В 13.0.4 конфигурация AnchorGram явно задаёт production, сохраняя обычный выбор из профиля для других способов подписи. Это исправляет подготовку разрешения, но не подтверждает доставку.

Для доставки в фоне также нужны:
- разрешённые уведомления AnchorGram в настройках iPhone;
- действительная подпись с aps-environment=production и тем же Bundle ID;
- APNs-сертификат приложения, подключённый к его API-приложению на my.telegram.org/apps. Сертификат установки ESign и API ID/Hash сами по себе не настраивают серверную доставку.

Для APNs-сертификата нужен доступ к Apple Developer для используемого App ID. Пока его подключение на стороне Telegram не подтверждено, уведомления при свёрнутом приложении не обещаются. Отсутствие расширения NotificationService ограничивает обработку содержимого уведомлений; его включение само по себе не создаёт серверную доставку.

Не меняй Bundle ID и не удаляй приложение для проверки: это может лишить доступа к текущим локальным данным. Проверять нужно подписанную IPA и логи регистрации APNs, а не только исходники.

Источники: https://core.telegram.org/api/push-updates и https://developer.apple.com/documentation/usernotifications/registering-your-app-with-apns
